# UD1 — Introducción a Big Data

Esta unidad introduce el problema Big Data, la calidad de datos y las primeras decisiones de arquitectura. El objetivo no es memorizar herramientas, sino entender cuándo un sistema de datos necesita otro enfoque.

La ruta combina **guías breves** y **capítulos ampliados**. Las guías sirven para
trabajar en clase y preparar actividades; los capítulos ampliados son la teoría de
apoyo cuando un concepto no quede claro o cuando haya que justificar una decisión
con más precisión.

## Ruta de trabajo

1. Empieza por el [problema Big Data y sus conceptos esenciales](../ud01-introduccion-big-data/01-teoria/01-fundamentos-big-data/UD1_01_BigData101.md). Es la lectura de arranque: presenta el caso, el vocabulario mínimo y las primeras decisiones.
2. Usa el [capítulo de fundamentos](../ud01-introduccion-big-data/01-teoria/01-fundamentos-big-data/UD1_Fundamentos_Big_Data_Ampliado.md) como teoría completa de apoyo: desarrolla las 5V, formatos, data lake/warehouse/lakehouse, ETL/ELT y coste-calidad-tiempo con más contexto.
3. Antes de interpretar resultados, trabaja la [estadística aplicada para Big Data](../ud01-introduccion-big-data/01-teoria/00-estadistica-y-base-matematica/UD1_P0_Estadistica_para_BigData.md) y la [cápsula matemática normativa](../ud01-introduccion-big-data/01-teoria/00-estadistica-y-base-matematica/UD1_P0_Capsula_Matematica_Normativa.md).
4. Continúa con [EDA y calidad de datos — guía práctica](../ud01-introduccion-big-data/01-teoria/04-eda-calidad-duckdb/UD1_02_EDA_y_calidad.md). Si necesitas más explicación sobre métricas, outliers, valores faltantes o trazabilidad, consulta también el [capítulo ampliado de EDA y calidad](../ud01-introduccion-big-data/01-teoria/04-eda-calidad-duckdb/UD1_EDA_y_Calidad_Capitulo_Ampliado.md).
5. Compara el [modelado documental y analítico](../ud01-introduccion-big-data/04-evaluacion/UD1_02_Tarea_Modelado_Documental_y_Analitico.md): documentos JSON frente a Parquet/DuckDB; MongoDB queda como ampliación opcional.
6. Practica con el [laboratorio de logs JSON](../ud01-introduccion-big-data/03-practicas/eda-calidad-duckdb/lab_logs_json/UD1_Lab_Logs_JSON.md).
7. Después, estudia [arquitecturas Big Data](../ud01-introduccion-big-data/01-teoria/03-arquitecturas-big-data/UD1_Arquitecturas_Big_Data.md) y realiza la actividad de diseño Medallion.
8. Cierra la parte práctica con la [tarea de EDA y su rúbrica](../ud01-introduccion-big-data/04-evaluacion/UD1_03_Tarea_y_rubrica.md).

## Después de esta unidad

Deberías poder explicar qué problema resuelve Big Data, qué significa calidad de datos y por qué una arquitectura Medallion separa datos originales, datos limpios y datos listos para análisis. También deberías distinguir qué arquitecturas son centrales para este módulo —lakehouse/Medallion y eventos/streaming— y cuáles sólo conviene conocer como contexto —Data Mesh, Data Fabric o HTAP—.

La estadística aplicada es una herramienta transversal de esta ruta: permite
interpretar las distribuciones, gráficos, anomalías y métricas de calidad que
aparecen al explorar o transformar los datos. No se considerará que una tabla o
un gráfico “habla por sí solo”: habrá que justificar qué significa y qué límites
tiene.
